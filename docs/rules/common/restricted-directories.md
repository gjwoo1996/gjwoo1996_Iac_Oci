# 디렉토리 읽기 제한 규칙

**규칙 ID:** `common/restricted-directories`  
**적용 대상:** 이 프로젝트에서 작업하는 모든 AI  
**적용 범위:** 파일 조회, 코드 분석, 검색, 요약, 자동 수정 등 모든 작업

---

## 원칙

### 1. 읽기 제한 디렉토리 준수 원칙

AI는 사용자가 읽지 말라고 지정한 디렉토리와 파일을 **열람, 검색, 요약, 분석하지 않는다.**

읽기 제한은 다음 작업에 모두 적용된다:

- `cat`, `sed`, `less` 등으로 파일 내용을 직접 확인하는 행위
- `rg`, `grep`, `find` 등으로 제한 디렉토리 내부를 검색하는 행위
- IDE, MCP, 플러그인, 외부 도구를 통해 제한 디렉토리 내용을 가져오는 행위
- 제한 디렉토리의 내용을 기반으로 코드 수정, 문서 작성, 요약을 수행하는 행위

### 2. 제한 목록 확인 원칙

AI는 작업을 시작하기 전에 이 문서의 제한 목록을 확인하고, 명령어 실행 시 제한 디렉토리가 포함되지 않도록 한다.

특히 전체 저장소 검색을 수행할 때는 제한 디렉토리를 제외하는 옵션을 사용한다.

**예시:**

```bash
rg "검색어" -g '!제한디렉토리/**'
```

### 3. 예외 승인 원칙

제한 디렉토리를 읽어야만 작업을 진행할 수 있는 경우, AI는 먼저 사용자에게 다음 내용을 설명하고 명시적인 승인을 받아야 한다.

- 어떤 디렉토리 또는 파일을 읽어야 하는지
- 왜 읽어야 하는지
- 읽지 않을 경우 어떤 작업이 제한되는지

사용자의 명시적 승인 없이는 제한 디렉토리를 읽지 않는다.

### 4. 문서 규칙의 한계

이 문서는 AI와 개발자가 따라야 할 작업 규칙을 정의한다. 하지만 파일 시스템 권한, 샌드박스, 도구 설정을 직접 변경하지는 않는다.

민감 정보 보호가 필요한 경우에는 이 문서와 함께 다음 조치를 추가로 적용한다:

- 민감 디렉토리를 저장소 밖으로 분리
- 파일 시스템 권한 제한
- 도구별 ignore 또는 exclude 설정 적용
- 비밀 정보는 환경 변수, secret manager, 암호화된 저장소로 관리

현재 읽기 제한 디렉토리는 아래에 추가한다.

| 경로 | 제한 이유 | 예외 조건 |
|------|-----------|-----------|
| `notes/` | 개인 메모 또는 작업 노트가 포함될 수 있으므로 AI가 읽지 않음 | 사용자가 특정 작업에서 명시적으로 읽기 승인한 경우 |

## AI를 위한 작업 전 체크리스트

AI는 파일을 읽거나 검색하기 전에 다음을 확인한다:

- [ ] 읽기 제한 목록을 확인했는가?
- [ ] 전체 저장소 검색 시 제한 디렉토리를 제외했는가?
- [ ] 제한 디렉토리를 읽어야 한다면 사용자에게 먼저 승인받았는가?
- [ ] 제한 디렉토리 내용을 추정하거나 간접적으로 요약하지 않았는가?
